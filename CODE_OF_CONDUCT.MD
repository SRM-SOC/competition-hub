# Code of Conduct — SRM-SOC

## Our Pledge

SRM Summer of Code is a community-first competition. We are committed to making participation a harassment-free, welcoming experience for everyone — regardless of age, background, experience level, gender, nationality, religion, or any other personal characteristic.

We pledge to act in ways that contribute to an open, respectful, and collaborative community.

---

## Our Standards

### ✅ Expected behaviour

- Be kind and respectful in all interactions — on Discord, GitHub, and anywhere SRM-SOC is discussed
- Give and receive constructive feedback graciously
- Help beginners — everyone starts somewhere
- Ask for help when stuck rather than silently struggling
- Give credit when your work is inspired by or builds on someone else's
- Follow all competition rules as described in [CONTRIBUTING.md](./CONTRIBUTING.md)

### ❌ Unacceptable behaviour

- Harassment, bullying, or intimidation of any kind
- Discriminatory jokes or language
- Dismissing or belittling other participants' contributions
- Plagiarising another participant's PR or code
- Creating multiple accounts to game the leaderboard
- Publicly shaming someone for a mistake or a beginner question
- Spamming issues, PRs, or Discord channels
- Any form of cheating or gaming the points system
- Sharing another participant's personal information without consent

---

## Competition-Specific Rules

These apply specifically to the competition environment:

1. **One account per person.** Creating multiple GitHub or Discord accounts to earn extra points = permanent ban.

2. **No plagiarism.** Copying another participant's PR — even with minor changes — is cheating. Both parties may be disqualified if intent is unclear.

3. **Claim honestly.** Don't claim issues you don't intend to work on. It blocks other participants. Hoarding claims will result in a warning, then a ban.

4. **No unsolicited PR help.** Don't push changes to someone else's fork or submit a PR that solves an issue already claimed by someone else (unless it's an `open` type issue).

5. **Respect maintainers' decisions.** If your PR is rejected, accept the feedback professionally. Maintainers have the final say on merges.

---

## Reporting a Violation

If you experience or witness unacceptable behaviour:

- **Discord** — DM any `@Maintainer` or `@Admin` directly
- **GitHub** — Use the "Report content" option on any issue or PR
- **Email** — [YOUR_EMAIL@srm.edu.in]

All reports are handled confidentially. You will not face retaliation for reporting in good faith.

---

## Enforcement

Maintainers and organisers are responsible for enforcing this Code of Conduct. Violations are handled as follows:

| Severity | Action |
|---|---|
| Minor (first offence) | Private warning |
| Repeated minor or moderate | Public warning + temporary Discord/GitHub suspension |
| Severe (plagiarism, harassment, cheating) | Permanent ban from competition, forfeiture of all points |

Maintainers have the right to remove, edit, or reject any contribution that violates this Code of Conduct, and to disqualify participants whose behaviour is harmful to the community.

---

## Scope

This Code of Conduct applies to all SRM-SOC spaces — GitHub repositories, Discord server, leaderboard website, and any other official communication channels. It also applies when representing SRM-SOC publicly (e.g. mentioning it on LinkedIn or social media in a way that reflects on the community).

By participating in SRM-SOC, you agree to abide by this Code of Conduct. Organisers reserve the right to update these guidelines at any time with reasonable notice to the community.
